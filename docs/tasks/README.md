# 작업 목록 (tasks)

마일스톤마다 구현 전에 작업 문서를 쓰고, 승인을 받은 뒤 구현한다.

## 흐름

1. [spec.md](../spec.md)에서 이번 마일스톤의 요구사항 ID를 고른다. `[NEEDS CLARIFICATION]`이 남은 기준은 고르지 않는다.
2. [design/](../design)과 [plan.md](../plan.md)를 바탕으로 `Mx-<이름>.md`를 쓴다. 상태는 `Draft`.
3. 리뷰 후 상태를 `Approved`로 바꾸고 구현한다.
4. 구현 중 문서와 다르게 해야 하면 문서를 먼저 고친다. 요구사항이 바뀌면 spec.md, 설계가 바뀌면 design 또는 ADR을 고친다.
5. 모든 작업의 검증이 끝나면 상태를 `Done`으로 바꾼다.

## 문서 형식

```md
# Mx. 제목

- 상태: Draft | Approved | Done
- Phase: (plan.md의 Phase)
- 요구사항: AUTH-01, AUTH-02 ... (없으면 "없음 (기반 작업)")
- 설계: design/backend.md 3.8 ...

## 목표

이 마일스톤이 끝나면 무엇을 시연할 수 있는지 한두 줄.

## 작업

- [ ] T1. 작업 이름
  - 파일: 만들거나 바꾸는 파일
  - 근거: 요구사항 ID 또는 설계 문서 절
  - 검증: 통과해야 하는 테스트나 명령

## 완료 기준

plan.md 5장 공통 기준 + 이번 마일스톤의 시연 항목.

## 결정 사항

구현 중 정한 것과 이유. 다른 문서에 반영했으면 위치를 적는다.
```

## 규칙

- 요구사항 ID가 있는 작업은 그 ID를 테스트 이름이나 설명에 넣는다. 예: `it('AUTH-04 5회 실패하면 잠근다')`
- 작업 하나는 한 번의 리뷰로 볼 수 있는 크기로 나눈다.
